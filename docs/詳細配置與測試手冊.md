# LDAPI 詳細配置與完整測試手冊

本文件提供 LDAPI 1.0.0 在 Paper 1.12.2、Java 8 環境下的完整配置方式、測試步驟、預期結果與故障排除。

> 本文件是配置與測試指南，不代表所有 YAML 欄位都會由目前版本的每一個 Manager 使用。實際生效欄位以對應 Java Manager 的讀取路徑為準。新增欄位前，請先在測試伺服器驗證。

---

## 1. 測試環境

建議建立獨立測試伺服器：

```text
Minecraft：1.12.2
伺服器核心：Paper 1.12.2
Java：8
LDAPI：1.0.0
MythicMobs：4.13.0（可選）
```

啟動參數範例：

```bash
java -Xms1G -Xmx2G -jar paper-1.12.2.jar nogui
```

不要在正式伺服器直接測試新的 YAML。先複製一份測試世界與 `plugins/LDAPI/` 資料夾。

---

## 2. 配置檔案與優先順序

```text
plugins/LDAPI/
├─ config.yml
├─ config/
│  ├─ general.yml
│  ├─ items.yml
│  ├─ attributes.yml
│  ├─ jewelry.yml
│  ├─ spaces.yml
│  ├─ commands.yml
│  ├─ tests.yml
│  ├─ shop.yml
│  ├─ dailyreward.yml
│  └─ mythicmobs.yml
└─ playerdata/
   └─ <玩家 UUID>.yml
```

目前 `ConfigManager` 會載入 `config/` 下的獨立 YAML；`config.yml` 則由 Bukkit 的 `JavaPlugin` 配置系統載入。若同一功能同時在兩個位置設定，請以實際 Manager 讀取的路徑為準，不要假設兩者會自動合併。

建議原則：

1. `config.yml` 保留主系統設定與舊版相容設定。
2. `config/` 放置分系統配置。
3. 不要刪除頂層節點名稱，例如 `items:`、`jewelry:`、`mythicmobs:`。
4. 新增物品時，同時確認 `items.yml` 的 ID 與商店、每日獎勵、MythicMobs 配置中的 ID 一致。

## 3. YAML 基本規則

### 3.1 縮排

正確：

```yaml
items:
  growth_core:
    material: EMERALD
```

錯誤：

```yaml
items:
 growth_core:
  material: EMERALD
```

建議每一層使用兩個空格，禁止 Tab。

### 3.2 字串與特殊字元

含有 `:`、`#`、`{}`、`[]` 或顏色碼的文字，建議使用雙引號：

```yaml
message: "&e獎勵：{gold} 金幣"
permission: ""
```

### 3.3 布林值與數字

使用真正的 YAML 型別，不要把數字寫成不必要的字串：

```yaml
enabled: true
chance: 0.25
price: 100
```

### 3.4 Material

Material 必須是 1.12.2 Bukkit / Spigot API 存在的名稱。不要直接使用 1.13+ 的 Material 名稱，也不要使用 `RING` 這類不存在於 Bukkit 1.12.2 的 Material；戒指應使用實際物品，例如 `DIAMOND`、`GOLD_INGOT` 或 `ENDER_PEARL`。

## 4. `config/general.yml`

```yaml
general:
  prefix: "&d[LDAPI] &r"
  debug: false
  command-prefix: ld
  lore:
    enabled: true
    ignore-color: true
    id-keys:
      - indierpg-id
      - item-id
      - mythic-id
      - namespace
      - jewelry-id
      - card-id
      - soul-bead-id
```

欄位說明：

| 欄位 | 說明 |
|---|---|
| `prefix` | LDAPI 訊息前綴，`&` 顏色碼會轉換成 Minecraft 顏色。 |
| `debug` | 除錯開關；正式環境建議關閉。 |
| `command-prefix` | 文件與提示所使用的主命令名稱。 |
| `lore.enabled` | 是否使用 Lore 進行物品識別。 |
| `ignore-color` | 比對 Lore ID 時是否忽略顏色碼。 |
| `id-keys` | 可用來辨識物品的 Lore key。 |

建議每個自訂物品至少放置一個穩定 ID：

```yaml
lore:
  - "&7item-id: growth_core"
```

## 5. `config/items.yml`

完整範例：

```yaml
items:
  growth_core:
    id: growth_core
    namespace: ldapi:item
    material: EMERALD
    display-name: "&b成長核心"
    lore:
      - "&7item-id: growth_core"
      - "&7namespace: ldapi:item"
      - "&7右鍵不觸發功能，作為成長素材使用"
    amount: 1

  space_ring_basic:
    id: space_ring_basic
    namespace: ldapi:spacering
    material: GOLD_INGOT
    display-name: "&a基礎空間戒指"
    lore:
      - "&7item-id: space_ring_basic"
      - "&7namespace: ldapi:spacering"
      - "&7右鍵開啟基礎空間"
    amount: 1
```

注意：

- `id`、區塊名稱與其他配置引用的 ID 應保持一致。
- `amount` 應為正整數。
- `material` 寫錯時，物品可能無法建立或被 Manager 跳過。
- MythicMobs 獎勵的 `item` 必須指向這裡存在的 ID。

測試命令：

```text
/ld items
/ld give growth_core
/ld give space_ring_basic
```

預期結果：物品成功出現在玩家背包，Lore 中能看到對應 ID。

## 6. `config/attributes.yml` 與 `config/jewelry.yml`

### attributes.yml

```yaml
attributes:
  attack:
    display-name: "&c攻擊力"
    default: 0
    min: 0
    max: 1000000
  defense:
    display-name: "&9防禦力"
    default: 0
    min: 0
    max: 1000000
  health:
    display-name: "&a生命值"
    default: 20
    min: 0
    max: 1000000
```

### jewelry.yml

```yaml
jewelry:
  enabled: true
  slots: 9
  definitions:
    abyss_ring:
      id: abyss_ring
      namespace: ldapi:jewelry
      name: "&5深淵戒指"
      material: DIAMOND
      base-attributes:
        attack: 10
        defense: 5
      growth:
        max-level: 50
        sources:
          - online-time
          - real-time
          - special-item
        per-level:
          "1": {attack: 1.0, defense: 0.5}
          "2": {attack: 1.5, defense: 0.8}
          "3": {attack: 2.5, defense: 1.2}
        default-per-level: {attack: 1.0, defense: 0.5}
```

欄位說明：

- `base-attributes` 是飾品基礎值。
- `max-level: -1` 代表不限制等級；測試環境可先使用 `50` 防止誤加過高。
- `per-level` 的 key 建議用引號，避免 YAML 把數字解析成不同型別。
- 未列出的等級使用 `default-per-level`。
- 屬性名稱必須與 `attributes.yml` 一致。

測試：

```text
/ld give abyss_ring
/ld admin setlevel <玩家> abyss_ring 3
/ld admin addgrowth <玩家> abyss_ring 10
```

預期結果：玩家資料更新，飾品等級與成長值沒有出現負數或超過上限。

## 7. 空間、商店與每日獎勵

### spaces.yml

```yaml
spaces:
  enabled: true
  default-space: basic
  definitions:
    basic:
      id: basic
      display-name: "&a基礎空間"
      size: 27
      permission: ""
    advanced:
      id: advanced
      display-name: "&9進階空間"
      size: 54
      permission: ldapi.space.advanced
```

`size` 使用 9 的倍數；權限為空字串表示不要求權限。

### shop.yml

```yaml
shop:
  enabled: true
  menu-title: "&6&lLDAPI 商店 &7[金幣：{gold}]"
  items:
    growth_core:
      price: 80
      item: growth_core
      slot: 11
    space_ring_basic:
      price: 500
      item: space_ring_basic
      slot: 15
```

測試重點：

- 金幣不足時不能購買。
- 購買成功後金幣扣除一次。
- 物品 ID 不存在時不應給出空物品。
- 關閉商店再重新開啟，GUI 不應重複註冊。

### dailyreward.yml

```yaml
dailyreward:
  enabled: true
  cooldown-hours: 24
  message: "&e[每日獎勵] &7第 {day} 天：+{gold} 金幣，+{xp} XP"
  rewards:
    day1: {gold: 100, xp: 25, item: growth_core}
    day2: {gold: 150, xp: 30, item: ""}
    day7: {gold: 1000, xp: 200, item: space_ring_basic}
```

測試時請使用測試玩家資料，不要直接修改正式玩家 UUID 檔案。確認第一次領取成功，冷卻期間不能重複領取，且重啟後領取狀態仍存在。

## 8. MythicMobs 完整測試配置

`config/mythicmobs.yml`：

```yaml
mythicmobs:
  enabled: true
  api-version: "4.13.0"
  events:
    ldapi_boss:
      spawn:
        skill: LDAPI_BOSS_SPAWN
      death:
        chance: 1.0
        skill: LDAPI_BOSS_DEATH
        gold: 500
        battlepass-xp: 50
        item: growth_core
        command: ""
```

MythicMobs 怪物範例：

```yaml
LDAPI_Boss:
  Type: ZOMBIE
  Display: '&cLDAPI Boss'
  Health: 100
  Damage: 8
```

技能範例：

```yaml
LDAPI_BOSS_SPAWN:
  Skills:
  - message{m="&cBoss 出現了！"} @PlayersInRadius{r=20}

LDAPI_BOSS_DEATH:
  Skills:
  - message{m="&6Boss 被擊敗！"} @PlayersInRadius{r=20}
```

重要：配置中的 key 必須使用 MythicMobs 回傳的 internal name。若怪物定義使用 `LDAPI_Boss`，請確認 LDAPI 的事件 key 與實際 API 回傳名稱一致；不同 MythicMobs 版本可能對名稱大小寫或取值方式不同。

測試順序：

1. 啟動伺服器，確認 MythicMobs 先載入。
2. 確認控制台顯示 `MythicMobs API 整合已啟用`。
3. 使用 MythicMobs 指令召喚測試怪物。
4. 確認生成技能執行一次。
5. 由玩家擊殺怪物。
6. 確認死亡技能執行、金幣增加、BattlePass XP 增加、物品加入背包。
7. 將 `chance` 改為 `0.0`，確認獎勵不發放。
8. 將 `chance` 改為 `1.0`，確認獎勵必定發放。
9. 由非玩家方式清除怪物，確認不會錯誤發放玩家獎勵。

## 9. 建置與啟動測試

### 建置

```bash
mvn clean package
```

預期輸出：

```text
target/LDAPI-1.0.0.jar
BUILD SUCCESS
```

### 首次啟動

確認：

- 插件成功載入。
- `plugins/LDAPI/config/` 建立。
- 預設 YAML 成功複製。
- 沒有 `InvalidPluginException`。
- 沒有 `FileNotFoundException`。
- 沒有 YAML parse error。

### 重載測試

```text
/ld info
/ld reload
```

修改一個訊息或獎勵數值後重載，確認新值生效。若修改的是 MythicMobs 自己的技能，還要使用 MythicMobs 的 reload。

## 11. 常見錯誤處理

### `Unknown material`

原因通常是使用了 1.13+ 或不存在的 Material。改成 1.12.2 可用名稱，例如 `DIAMOND`、`EMERALD`、`GOLD_INGOT`。

### `找不到物品`

檢查：

1. `items.yml` 是否存在該 ID。
2. 引用時大小寫是否一致。
3. YAML 是否有縮排錯誤。
4. 是否執行 `/ld reload`。

### MythicMobs API 沒有啟用

檢查：

1. MythicMobs 是否真的安裝在 `plugins/`。
2. 插件名稱是否為 `MythicMobs`。
3. 版本是否為相容的 4.x，建議 4.13.0。
4. 控制台是否有 API 版本錯誤。
5. 是否在 MythicMobs 載入完成前啟動 LDAPI。

### YAML 讀取錯誤

先把最近修改的區塊還原，再用 YAML 編輯器檢查：

- Tab。
- 少了冒號。
- 引號未關閉。
- 重複的 key。
- 列表項目縮排不一致。

### 修改後沒有生效

不是所有配置都一定能透過熱重載完全更新。建議：

1. 執行 `/ld reload`。
2. 查看控制台。
3. 若仍無效，完整重啟測試伺服器。
4. MythicMobs 技能則使用 MythicMobs 自己的 reload。

## 12. 發佈前建議

完成所有測試後：

1. 備份 `plugins/LDAPI/` 與測試世界。
2. 執行 `mvn clean package`。
3. 確認 JAR 內有 `plugin.yml` 與預設配置資源。
4. 確認 README、Release Notes 與實際命令一致。
5. 確認 README 沒有宣稱尚未實作的功能。
6. 使用全新伺服器進行一次乾淨安裝測試。
